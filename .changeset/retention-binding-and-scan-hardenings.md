Three fail-closed hardenings from the wave 2b gate review. (1) Retention carries the prior binding hash: when a rejected regeneration retains the previously published page, the prior shard's recorded `mdxContentHash` carries forward unchanged and the retained MDX bytes are verified against it — a prior shard with no hash, or bytes that no longer match (one-sided edit, interrupted prior write), persists WITHOUT a binding so emission renders the page loud-UNVERIFIED instead of blessing unknown bytes; the hash is minted fresh only over bytes the kernel itself writes in the same run. (2) Duplicate marker attributes are rejected at scan: `<Claim id="a" id="b">` (any repeated attribute name) is a precise in-session repair error, and post-acceptance a kernel invariant breach — the scanner reads the first id while JSX rendering uses the last, so the trust mark would attach to the wrong claim. (3) Raw `<script>` and `<style>` elements anywhere in submitted MDX are rejected at submit_page (case-insensitive, JSX-element and raw-HTML forms): generated pages must not carry executable or style elements — the theme owns page behavior; code fences showing example markup remain untouched.
