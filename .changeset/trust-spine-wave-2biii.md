Behavior claims are checked only through DECLARED execution coverage: code fences name the claims they exercise via `covers=<markerId>,…`, validated at submit time and returned by the snippet-exec verifier on pass — same-section proximity proves nothing. After retry exhaustion with blocking claim findings, a previously published page is retained byte-for-byte (the rejected candidate is journaled and flagged); a first generation persists its contradicted ledger state explicitly. Claim identity matching is solved as bipartite components with per-block thread confidence — every ambiguous thread records a typed drift marker and orphans persist on the shard.
