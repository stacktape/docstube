Two wave 2b close fixes. (1) THE MDX VERIFIER COMPILES THE BODY, NOT THE RAW FILE: frontmatter is YAML, but the verifier handed the whole file to the MDX compiler, which read the frontmatter block as prose — so a correct authored value such as `description: "Use <Widget> literally"` failed as an unclosed JSX tag on a page Astro accepts, and a false compile error is a build the user cannot make green by writing correct docs. The two halves are now checked by their own parsers: the fenced block by the YAML parser (unchanged), the body by the MDX compiler. Because the compiler now sees body-relative coordinates, every reported line is shifted back onto source lines before a human reads it — including the position micromark bakes into its message text, which is dropped rather than left as an unshifted duplicate pointing at the wrong line. (2) THE GENERATED SITE'S MCP SERVER MIRRORS THE CANONICAL FRONTMATTER RULES: the docs MCP server emitted into every site strips frontmatter with its own inline rule, because it ships standalone into sites that never depend on `@docstube/*` at runtime. That copy had gone stale and stayed strict, so a page written with a UTF-8 BOM or a blank line above its `---` leaked its frontmatter into `ask_question` keyword scoring and into the text the tool returns — the server would answer a question by matching a `description:` value the reader never sees. It now applies the same tolerant rules as `@docstube/contracts`, and both files carry a comment naming contracts as the source of truth so the two are updated in lockstep.
