# i18n lifecycle v2 — founder decisions (2026-07-19)

Source: Sol xhigh design review domains 03 (i18n lifecycle) and 04 (translation architecture),
adjudicated by the founder. Binding for 0.1.0, alongside trust-model-v2.md. Foundational
correction from the founder: translations are ALWAYS AI-generated by the pipeline — no human
translation workflow exists or is planned. And a standing tenet recorded at the same time:
**minimize human review everywhere; docstube's default posture is autonomous with visible
outcomes, never approval gates.**

## Decisions

1. **Partial locales serve source fallbacks.** An untranslated or failed page renders the fresh
   source content under the locale route with a visible "not yet translated" banner; nav shows
   everything with untranslated pages marked. Stale-but-verified translations stay reachable with
   a "content updated since translation" warning. No 404s, no hidden locales.

2. **Translation assurance = one bilingual fidelity review per page-locale revision**, judging
   meaning preservation, omissions/additions, negation/quantity changes, terminology, and claim
   anchors against normalized source units. Persona reviews are inherited from source, never
   rerun per locale. Same-model fidelity review is acceptable (founder call — simplicity over
   routing complexity); the assurance record notes the model used. One correction cycle on
   failure (failed candidate + findings fed back), then fallback.
   **Status (wave 2b close, 0.1.0):** the review itself is NOT implemented — it is built in the
   i18n wave, against `translationFidelitySchema`. What ships now is the honest interim surface
   required by decision 3: every shipped translation records `translationAssurance:
   'not-reviewed'` on its locale shard and every theme renders "Translation: not yet reviewed" as
   a distinct line beside the inherited correctness counts. Without it, a translation that flipped
   a negation or changed a number would read as fully checked, because renditions inherit the
   canonical shard's checked counts.

3. **Two-dimension proof UI.** Source correctness (claims checked — language-independent, per
   trust-model-v2) and translation assurance (fidelity-reviewed / pending / fallback) are shown
   as separate dimensions, never collapsed.

4. **Strict isomorphism.** Locales are renditions of one canonical structure: same entity and
   claim IDs, localized anchors, code blocks byte-identical by construction. The canonical claim
   ledger lives in the source locale; rendition evidence references canonical evidence at an
   exact source revision. No locale-specific content in v1.

5. **Translation failures are NONBLOCKING for auto-merge.** A failed page-locale serves the
   fallback (decision 1), reports as a localization-coverage finding ("49 ready · 1 failed") in
   the PR summary and dashboard, and never holds a source correction hostage. Persistent
   failures dead-letter: retried only when content/glossary/policy/model changes or on request.

6. **Versions × locales: cut anytime; sealed + explicit repair.** Version cutting never waits on
   localization; the snapshot records which pages fell back. Frozen snapshots never change on
   their own; `docstube version repair <label>` consciously backfills (recorded). New-locale
   backfill targets the current version only; frozen versions via explicit repair.

7. **Terminology profiles: auto-committed, no human gate** (founder delegated; per the
   minimal-review tenet). Adding a locale bootstraps a committed per-locale terminology profile
   (translate-to / keep-source / forbidden variants per glossary term) in two one-time calls;
   entries carry origin: ai, user edits carry origin: user and win permanently. Glossary changes
   invalidate only dependent units.

## Target architecture (Sol's, adopted — converged with the block-level proposal)

- **LocalizationPlan**: canonical MDX + claim ledger parse into ordered translatable UNITS
  (headings, paragraphs, list items, table cells, frontmatter title/description, localizable
  component props) with unitId, owning entity, source text hash, placeholder inventory, claim
  refs. Code, links, identifiers, component structure never enter model output.
- **Model call unit = page-locale batch** of changed units (context supplied read-only); the
  kernel validates the returned unit map (missing/duplicate/placeholder-altered rejected) and
  reassembles MDX from the canonical AST — structure correct by construction.
- **Translation memory** persists per unit: source text hash + locale pair + placeholder shape +
  relevant glossary revisions + policy version. Unchanged units never retranslate.
- **Localization scheduler** reconciles desired vs published per version × locale × page with
  states absent/pending/ready/stale/failed; every source-mutating command drives it; new-locale
  backfill enters here over committed source artifacts (no writer/verifier reruns).
- **Separate localization phase** after canonical source generation + topology checks, bounded
  concurrency grouped by locale, its own budget partition — locale spend can never freeze source
  generation.
- **Role routing made real**: translate-units → translator role (economy-class default);
  fidelity review → reviewer role. (Today agents.roles.translator is parsed but unrouted — a
  false affordance to fix.)
- **Publication states**: candidate vs published rendition vs route-fallback are distinct; emit
  consumes explicit route resolution, never infers from file presence.

## Cost model (adopted target)

2 model calls per page-locale initially (translate batch + fidelity); 0 for unchanged refreshes;
a 5-changed-pages refresh in a 100-page × 3-locale project costs ~30 calls (~95% fewer than
revisiting every page-locale); code-only changes cost zero localization calls. Terminology
bootstrap: 2 one-time calls per locale.

## Sequencing

Implemented together with the trust-model-v2 claim-ledger rework (the LocalizationPlan derives
from the same canonical parse). One migration while manifests are private.
