# Configuration

<Claim id="c1">`configFileNames.config` is docstube.yml.</Claim> <Claim id="c2">`configFileNames.ia` is ia.yml.</Claim>
<Claim id="c3">`configFileNames.glossary` is glossary.yaml.</Claim>

These files are the configuration family a maintainer edits when a repository's documentation intent changes. <Claim id="c4">`loadConfigFamily` reads `docstube.yml` and `ia.yml`.</Claim> <Claim id="c5">`loadConfigFamily` uses an empty glossary when `glossary.yaml` is absent.</Claim>

## Main Config

<Claim id="c6">`docstubeConfigSchema` requires `schemaVersion`.</Claim>
<Claim id="c7">`docstubeConfigSchema` requires `docType`.</Claim>
<Claim id="c8">`docstubeConfigSchema` requires `personas`.</Claim>
<Claim id="c9">`docstubeConfigSchema` requires `site`.</Claim>

The schema is strict: <Claim id="c10">`docstubeConfigSchema` rejects unknown top-level keys.</Claim> Keep `docstube.yml` focused on intent: project context, personas, source hints, agent routing, site metadata, localization, components, plugins, and output policy.

```yaml
schemaVersion: 1
docType: external-product
projectContext: >-
  Short description of what this project is and who the generated docs are for.
personas:
  - id: oss-maintainer
    description: Maintains the repository and reviews generated docs.
sources:
  openapi: []
  asyncapi: []
  imports: []
agents:
  transport: codex-cli
  model: gpt-5.5
  budgets:
    maxRunUsd: 100
    maxTurnsPerTask: 24
    maxToolCallsPerTask: 64
    maxPlanUsagePercent: 80
locales:
  source: en
  targets: []
theme:
  name: basic
site:
  title: My Project
  description: Verified documentation for My Project.
  layout: single-tree
components:
  - Callout
  - CodeBlock
plugins:
  - ./plugins/company-style.ts
```

## Budgets

<Claim id="c28">`agentsConfigSchema.budgets.maxRunUsd` defaults to 20.</Claim>
<Claim id="c29">`agentsConfigSchema.budgets.maxTurnsPerTask` defaults to 24.</Claim>
<Claim id="c30">`agentsConfigSchema.budgets.maxToolCallsPerTask` defaults to 64.</Claim>
<Claim id="c31">`agentsConfigSchema.budgets.maxPlanUsagePercent` defaults to 80.</Claim>

<Claim id="c32">`FREEZE_MARGIN_RATIO` is 0.85.</Claim>
<Claim id="c33">
  `createRunCostTracker` freezes a run when reported and estimated spend reaches 85 percent of `maxRunUsd` without a
  plan-usage signal.
</Claim>
<Claim id="c34">`createRunCostTracker` freezes a run when plan usage reaches `maxPlanUsagePercent`.</Claim>
<Claim id="c35">`buildWritePageTask` uses `maxTurnsPerTask` for writer task turns.</Claim>
<Claim id="c36">`buildWritePageTask` uses `maxToolCallsPerTask` for writer task tool calls.</Claim>

For maintainers, the practical split is simple: `maxRunUsd` is the run cap, `maxPlanUsagePercent` is the subscription plan cap, and per-task turn and tool-call limits bound individual writer tasks.
